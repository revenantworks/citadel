# Pack Registry — structural single source of truth *(event-driven surface)*

> The canonical roster and pack structure `tools/build.py` derives every
> `references/pack.md` from. **Event-driven** — updated on roster or pack
> changes only, not on a calendar (no staleness stamp). Holds only what a
> *build* needs to name and stamp a member. Brand **styling** — palette, voice,
> taglines, wordmark, firewall — does **not** live here; it lives in
> brandwright's `brand-definition.md` and is applied only when brandwright is
> invoked. The token below is a **label** (it names skills and stamps
> frontmatter); it applies no styling on its own.

## Build defaults

| Parameter | Value |
|---|---|
| Brand token *(label)* | `revenant` — names skills (`<brand>-<pack>-<skill>`) and stamps `metadata.brand`; a label, not applied styling |
| Naming template | `<brand>-<pack>-<skill>` (64-char guard) |
| License default | MIT |
| Packaging default | Folder-zip, full files including `evals/`, folder at top level, named `<n>-<version>.zip` — `.skill` on request |

**foundation budgets** *(body-footprint table — one row per member; `build.py` validates each member's measured SKILL.md body against its row)*

Declared here rather than in each member's frontmatter, changed 2026-07-27. The gate is unchanged — a body's size must be **declared and justified**, per the item-③ rescope — but the justification is build-time data, and frontmatter is loaded on every single invocation of the skill. A `why` in `metadata.body_budget` cost 51–95 tokens per member *every time that member ran*, to explain a number no runtime reader ever acts on. That is the exact waste tokenwright exists to find, sitting in the pack's own gate. The registry is already `build.py`'s single source of truth, no member loads another member's registry, and nothing here ships in a member's zip — so a row costs zero runtime tokens. **That is what makes declaring all eight affordable**: eight frontmatter blocks would have cost ~400 tokens per session to say that five members have no size problem.

**Standalone skills built outside a pack keep `metadata.body_budget` in frontmatter** — they have no registry to declare into, so the frontmatter form stays valid and `build-templates.md` still teaches it. It is the pack-member case that moves.

**foundation seams** *(routing-seam table — one row per boundary pair; pack manifests are generated from this table too)*

| Seam | Left owns | Right owns | Router keys on | Cold-listing signal |
|---|---|---|---|---|
| promptwright ↔ tokenwright | What the prompt says and how well it performs — wording, structure, hardening, scoring, and the run-target tier pick | What the artifact costs — behavior-preserving trims, budgets, cached-prefix fit, waste audits | The stated motive. A cost cue (cheaper, too many tokens, fits the budget) is tokenwright; a quality cue (works better, stop the rambling, fix the output) is promptwright. A bare "tighten this prompt" carries neither and stays promptwright — the trim carve-out only sends work away when behavior is explicitly held constant | both descriptions |
| skillwright ↔ lorewright | Whether a skill or pack idea fills a real niche — the verdict on a skill, however heavily sourced | Sourced, evidence-graded go/no-go and comparison verdicts on everything that is not a skill | The object under judgement, not the sourcing verb. | skillwright ↔ brandwright | Executing a change across a skill set — port, rename, rebrand, sanitize for a new owner — and the propagation that follows (registry rows, manifests, packages) | Defining a brand or voice, applying it on invoke, auditing a repo or skill set for drift, exporting payloads and the guide card | Whether identity moves or only styling. | commwright ↔ brandwright | Applying a voice to the message in hand — one message out, the stored profile untouched | The voice itself — defining, saving, editing, restyling, or exporting a stored profile | Whether anything durable is created or changed. **foundation seam notes:** the **skillwright ↔ agentwright** row was added 2026-07-27 at pack 1.3.0, closing a boundary that shipped one pass earlier claimed from one side only. agentwright 1.2.0 and skillwright 1.4.0 each took a security capability and each wrote a reciprocal boundary sentence into its own `description`, but the row itself was deliberately skipped that pass because adding it regenerates all eight manifests — so the seam existed in routing metadata and nowhere the table could see it. Recorded plainly because it is the class of gap this table exists to catch: `tools/build.py`'s boundary-pair check validates the rows that are declared and has no way to notice one that is missing, so a `--check` clean run was never evidence the seam was covered. The deciding word is **injection**, now in two descriptions at once — the first time any single security token has been — which is why the row keys on the object rather than the vocabulary and why skillwright trigger rows #38-#43 pair each security query against its opposite-object twin (#42 against #38 is the sharpest, #43 sits outside both on purpose).

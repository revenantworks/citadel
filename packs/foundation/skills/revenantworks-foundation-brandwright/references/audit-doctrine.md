# Audit Doctrine — Build Extraction Rules, Sweep Notes, Guide Card

Load on Build and Audit runs, and on the guide-card export for its fill rules at the bottom. The definition itself lives in `brand-definition.md`. Three of the four export shapes — voice profile, structural payload, style one-pager — are stated in full in the SKILL body's Entry — Export and bind whether or not this file is open; this file restates none of them. The fourth, the brand-guide card, carries its mandatory section order and fill rules here at the bottom and nowhere else — that is why a card export loads this file. This file carries the how.

## Build — the two extraction rules

The interview groups and the order they are asked in are stated in the SKILL body's Entry — Build and bind whether or not this file is open; this file names none of them, adds none, and reorders none. What is this file's own: two rules that shape how any answer is recorded. **Roles over values** — a hex without a role can't style an artifact type nobody anticipated. **Templates over examples** — one rendered name is an example; `<brand>-<pack>-<skill>` binds a class.

## Build — palette derivation

*Roles over values* says a palette is **recorded** as roles; these rules say where the values come from. Work in a perceptual space — OKLCH — because even lightness steps are the whole point of most of what follows and hex arithmetic cannot produce them. Every rule here was learned from a palette that looked finished and measured wrong, so each states a number to measure rather than an impression to check.

- **D-1 Neutrals are computed, not picked.** Generate the surface and border stack at the brand's own accent hue with perceptually even lightness steps, and record the hue it was generated at. Hand-picked stacks drift, and the drift hides per swatch: the classic form is a set of greys sitting ~76° off the accent they belong to — nearer a sub-brand's accent than their own — obvious only once the hue of every step is printed in one column. One system-wide neutral set is legitimate; what it may be shared *with* is `application-doctrine.md`'s.
- **D-2 Elevation needs a visibility floor.** Each surface step clears **~1.13:1** against the step below it. A "raised" surface at 1.05:1 is an elevation layer doing nothing — the token exists, the depth does not.
- **D-3 Split the border token.** A **quiet** border for ordinary structure, and a **lit** border clearing **3:1 on the surface it sits on** for load-bearing edges — focus, active, selected. One token cannot serve both: at 1.24:1 it is invisible exactly where it must be seen, and a palette whose only border cannot meet the graphics floor the same definition states is a palette violating its own accessibility rule.
- **D-4 Derive light from the accent's own lightness, never from the floor alone.** `lit L = max(accentL − 0.17, the L that clears 3:1 on its surface)` at chroma × 0.78; `glow L = max(accentL − 0.05, the L that clears 4.5:1 on the ground it sits on)` at chroma × 0.92. A high-lightness accent is driven by the first term and a low-lightness one by the floor, which is what the `max` is for. Hunting the *minimum* lightness that clears a floor instead imports one accent's lightness onto another and returns a muddied third hue; the real cost lands downstream, when that artifact gets written into the definition as a claim about the original hue. **The general rule this is one instance of: a rule tuned on one hue is re-tested against every accent in the definition before it becomes doctrine.**
- **D-5 Colour never carries state alone.** State is a form change **plus a word**; emphasis is a *different* form change. That separation is what lets one token serve both roles without ambiguity, and it is WCAG 1.4.1 — an accessibility-floor entry, not a preference.
- **D-6 A shared accent set is proved, not asserted.** A system keeping N shared accents so that one always works against whatever accent leads a surface carries a **coverage matrix**: ΔE00 from every brand accent to every shared accent, showing each surface has at least one clean option. Two findings ride with it. **Optimise the set jointly, not member by member** — a set whose members were each independently optimal scored **62%** of the achievable joint ceiling. And record where a **semantic constraint beats the chromatic optimum**: a status role whose meaning is bound to a hue family (an error reading reads red) keeps that family even when the coverage-optimal partner sits elsewhere on the wheel. That is a documented override, not a defect.
- **D-7 Separation is CIEDE2000, and the floor is regional.** State the tightest pair's ΔE00 as the threshold a new candidate must beat, and name where the wheel is crowded — a cluster drags the local floor below the global one, so a candidate landing in a cluster is judged against the cluster. Validate any ΔE00 implementation by reproducing a known recorded value before trusting a number it produces.

Which surfaces inherit which of these values — across sub-brands, across modes, and for a cross-brand mark — is `application-doctrine.md`'s and is not restated here.

## Audit — per-category sweep notes

The categories, their count, and their order are stated in the SKILL body's Entry — Audit and bind whether or not this file is open. What follows are glosses **keyed to that list, in its order** — one note per category, each opening with the body's own name for it verbatim, adding no category, reordering none, and never forming a count of its own that could drift from the body's. Sweep every file or surface in the target; the catalog cites file + line/location per finding.

- **naming-template conformance** — rendered names match the class template; segment order, casing, and separators exact.
- **palette drift** — colors in code, styles, and artifacts resolve to role tokens; off-token values are findings even when "close." Measured, not eyeballed, and **the neutrals are in scope**: an audit that scores the accents and never prints the hue and lightness of every surface and border step is how a stack tens of degrees off its own accent passes green. Recompute each ratio the derivation rules above state — surface against the surface below it, lit border on its surface, lit and glow against theirs — and report the number beside the verdict. Score the palette against **the definition's own accessibility floor** as well as its role tokens: a palette can conform to every token it declares and still fail a rule the same definition states.
- **typography & logo-usage drift** — faces off the type roles for the surface (body copy in a display or pixel face, wrong display face for the brand); wordmark misuse — stretched or off-token-recolored marks, clearspace or minimum-size violations, forbidden effects.
- **voice and register drift** — prose scored against attributes and the register map for its surface; docs vs. chat vs. titles each judged by their own register.
- **tagline/sign-off surface violations** — present only where the definition allows; absence where required is drift too.
- **stale identity strings** — old handles, org names, repo paths, and retired taglines from History notes; a rename that left the old string anywhere is the classic miss.
- **firewall breaches** — identities co-occurring on a surface the map forbids; the fix names which identity stays.

Scored on the SKILL body's anchors, one score per category; a mid-band score means an inconsistency a reader would notice. Overall = average of the scored categories, one decimal — **except when a P0 is open**, where Entry — Audit's P0 floor overrides this arithmetic; that override is stated there and binds whether or not this file is open, and this file does not restate it. A category with no applicable surface in the target is marked n/a, never padded — n/a categories are excluded from the average, not scored zero.

## Severity — the two bands below P0

P0's triggers are stated in Entry — Audit and bind whether or not this file is open; this file states neither them nor a fourth. **P1** — a violated convention the definition states (wrong name render, off-token palette, voice breach on a governed surface). **P2** — polish (inconsistent casing the definition doesn't govern, stale-but-harmless strings).

## Brand-guide card — fill rules

The one export that opens this file: Entry — Export states the card's envelope, this section states what goes inside it. One self-contained HTML file, fully offline — no external scripts, fonts, CDNs, network calls, or browser storage. **Exactly 12 sections, in this order:** header lockup (skill wordmark + guide title + definition-version chip) · essence · architecture (one card per identity with primary tagline) · palette (core, functional, identity accents — swatches with name + hex, tap/click-to-copy) · typography table (rendered in fallback stacks, noting brand faces install separately) · tag registry · naming quick rules · voice cards with sign-offs · wordmark + logo rules · motion/imagery/application/accessibility digest · firewall · footer echoing the lockup, definition version, and date. Styled from the active definition's own tokens; with none stored, the neutral dark theme. Respect reduced-motion.

**Every section renders from a definition section — the card collects nothing of its own.** Each of the twelve draws on the definition group of the same name; the two that do not map by name are stated here. **Tag registry** renders from the **identity map** — its handles/orgs and community terms rows, each listed with the identity that owns it and the surfaces it is allowed on, taglines and sign-offs included by their allowed-surface rule. It is a *view* of already-collected fields, not a group of its own: Entry — Build's fourteen groups collect no tags, and adding a fifteenth is not the fix. **Architecture** renders from the identity map's parent brand and sub-brands, one card each, carrying that identity's primary tagline. Where a source field is empty the section renders an explicit "none registered" row and is never omitted, never a stub, and never invented — the section count is fixed at twelve whatever the definition holds.

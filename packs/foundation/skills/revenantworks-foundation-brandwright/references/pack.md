# Pack — foundation *(standalone profile)*

**Routing seams** — one row per boundary pair: what each side owns, and the signal that decides. Same advisory standing as the roster; a row reading *none — table only* is a seam the cold listing cannot decide, recorded here rather than claimed.

**foundation seam notes:**

- **skillwright ↔ agentwright** (added 2026-07-27, pack 1.3.0): closed a boundary that shipped one pass earlier claimed from one side only. agentwright 1.2.0 and skillwright 1.4.0 each took a security capability and each wrote a reciprocal boundary sentence into its own `description`, but the row itself was deliberately skipped that pass because adding it regenerates all eight manifests — so the seam existed in routing metadata and nowhere the table could see it. Recorded plainly because it is the class of gap this table exists to catch: `tools/build.py`'s boundary-pair check validates the rows that are declared and has no way to notice one that is missing, so a `--check` clean run was never evidence the seam was covered. The deciding word is **injection**, now in two descriptions at once — the first time any single security token has been — which is why the row keys on the object rather than the vocabulary and why skillwright trigger rows #38-#43 pair each security query against its opposite-object twin (#42 against #38 is the sharpest, #43 sits outside both on purpose). Both sides carry the claim, so the signal reads **both descriptions**; the cold re-run that would instrument it is owed and disclosed, not claimed.

- **rigwright ↔ tokenwright** (added 2026-08-05, AUDIT-2026-08-05): opened by rigwright's 2026-07-30 addition — "trim a … CLAUDE.md" (rigwright) and "slim, compress, or token-optimize … CLAUDE.md" (tokenwright) shared an object with no declared row, and the naming note above still counted two CLAUDE.md descriptions. The clause lands on tokenwright's side only (1.1.0) — rigwright's description had 72 chars of headroom against the house warn band and its named-surface claim is the stronger side, the same asymmetry as promptwright ↔ lorewright — so the signal reads **one description**. The cold re-judge of tokenwright's trigger rows against the amended listing is owed and disclosed, not claimed.

- **`sanitize`** is object-decided: a skill set handed to a new owner is skillwright port, a brand identity swept across a tree is brandwright audit, a public-bound message is commwright's pre-publish redaction sweep.

- **skillwright ↔ commwright** (closed 2026-07-25 on one side, skillwright 1.3.0; scoped on the other 2026-07-27, commwright 1.2.6): skillwright's description now claims a prose pass on a skill's or pack's own files and names README and CLAUDE.md, and Entry — Audit carries the procedure that serves the claim, so "humanize the README" and "humanize my CLAUDE.md" have a positive file claim to land on instead of firing commwright. commwright's description's `humanize` clause now names the excluded objects (a README, CLAUDE.md, or reference doc is skillwright's prose, not commwright's), so both descriptions carry the boundary and the signal now reads **both descriptions**; commwright re-reasoned the three probes cold in its `evals/RESULTS.md`, discharging the routing re-run that close owed on the description surface. Two limits, recorded rather than papered over: the close holds in the pack-repo reading, since a README belonging to no skill or pack is claimed by neither side by design (it is skillwright trigger row #18), and the routing judgement behind it is authored, not instrumented — the re-run is owed.

- **Naming notes:** "prose" now appears in exactly one description (skillwright) and "style" still in exactly one (brandwright, "style guide"), where it means brand identity and never prose register; "CLAUDE.md" appears in three — tokenwright's, claimed for footprint only; skillwright's, claimed for wording only; and rigwright's, claimed for placement and setup (the count read two until 2026-08-05 — it predated rigwright's 2026-07-30 addition; corrected with the rigwright ↔ tokenwright row).

- **Third limit** (opened and closed 2026-07-25): the always-on router now carries the seam. `packs/foundation/CLAUDE.md` loads on every turn under `packs/foundation/`; it previously gave skillwright only "Build, audit, port, or pack a skill" while the table's one rewrite-flavoured cue was commwright's, so "humanize the writing in my pack's README" met a standing surface naming commwright and never skillwright. The row now reads "…or a register pass on a skill's or pack's own files" with the cue "humanize / tighten this README", and a How-they-compose bullet states the split: prose on repo files is skillwright's, prose bound for a channel is commwright's, and the same content pasted into a release body is a message again. The close now holds on the surface that loads first as well as at the description level, where trigger rows #35-#37 measure it.
